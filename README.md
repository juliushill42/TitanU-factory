
This codebase is a highly resilient, defense-in-depth autonomous execution engine written in Rust. Its primary purpose is to safely orchestrate, inspect, and deploy code payloads (such as those generated by an AI agent) to a local filesystem while mitigating the catastrophic risks of prompt injection, directory traversal, malicious code execution, and system-level denial of service (DoS).

The design uses a Manager-Worker concurrent architecture with strict isolation patterns:

    Zero Lateral/Upward Trust: Workers operate in isolated threads, blind to each other, and can only communicate upward to the Manager via structured, un-exploitable "receipts."

    Deterministic Safety Over AI Guessing: Rather than using probabilistic methods (like an LLM checking its own output), it enforces strict, zero-tolerance mechanical gates (JSON validation, static token blacklists, WASM runner isolation, and resource-threshold monitoring).

Titan Factory: 5-Moat Autonomous Build Engine

TITAN FACTORY is a highly secure, concurrent execution broker written in Rust. It is designed to act as an impregnable security boundary between untrusted, autonomously generated code payloads (e.g., from LLMs/AI Agents) and actual system-level execution or deployment.

By passing inputs through five distinct structural and behavioral "moats," the architecture ensures that malicious payloads, injection attacks, resource-exhaustion exploits, or directory traversals are neutralized before they can permanently affect the host machine.
🏗 Architecture & Core Philosophy

The system implements a unidirectional, zero-shared-state concurrency model using Rust’s native threading and std::sync::mpsc channels.

The 5 Moats of Security
Layer	Component Name	Mechanism	Primary Threat Prevented
Moat 1	The Translator Gate	Strict structural deserialization via serde_json. Rejects extra fields, enforces path restrictions to ./output/, and limits payload size (< 64KB).	Prompt injection, Malformed schemas, Host directory traversal (../etc/passwd).
Moat 2	The Burner Sandbox	Instantiates an ephemeral, host-isolated embedded WebAssembly (wasmi) runtime with zero host functions/linkers imports.	Host resource hijacking, untrusted execution breakouts.
Moat 3	The Code Inspector	Deterministic static-string pattern token analysis using an un-bypassable blacklist targeting OS commands, networking, and memory tampering.	Shell execution (std::process::Command), forbidden network binding, memory access (/dev/mem).
Moat 4	Isolated Pipes	Unidirectional MPSC architecture. One isolated down-channel per worker; one cloned, write-only receipt channel up to the Manager.	Lateral movement, cross-worker snooping, malicious upward command querying.
Moat 5	Instant Delta Rollback	Byte-accurate file snapshots matched with microsecond post-deploy system health telemetry tracking via sysinfo.	Host DoS (CPU/Memory exhaustion loops), destructive file overwrites.
📂 Module Deep Dive
1. Main Core Orchestrator (main.rs)

The entry point initializes the communication fabric, registers the specified pool size (NUM_WORKERS), boots individual worker execution loops inside dedicated thread boundaries, and safely pumps an evaluation batch of distinct edge-case tasks into the cluster.
2. The Command Center (manager.rs)

The ManagerMote holds exclusive downwards write access to individual worker pipelines. It consumes raw tasks, passes them through Moat 1, and assigns them to targeted workers. Its close_and_drain sequence cleanly closes pipelines by dropping senders, forcing workers to drop out of their loops naturally, while consuming final audit logs.
3. Ingestion Sandbox (moat1_translator.rs)

Enforces formatting rigidity. Converts fluid, untrusted input structures into strict Rust enum variants (FeatureType). Ensures target paths never contain directory traversal fragments and stay pinned strictly inside the allowed namespace.
4. Ephemeral Runner (moat2_sandbox.rs)

Ensures compilation validation by validating the binary headers (\0asm) of WASM blobs. By instantiating a completely blank wasmi::Linker<()>, the payload runs inside a zero-linkage void, meaning it cannot access file I/O, networks, or host system variables.
5. Static Token Audit (moat3_inspector.rs)

A zero-cost, mechanical static analyzer that intercepts high-risk signatures (ptrace, chmod, TcpListener, etc.). It produces complete diagnostic reports detailing explicitly triggered violations.
6. Isolation Topology (moat4_pipes.rs)

The communications layout code. Wraps the channels to prevent code typos elsewhere from accidentally exposing reading ends to workers, or writing capabilities to managers. Returns abstract ExecutionReceipt structures containing only boolean statuses and logs.
7. Time Machine Rollback Engine (moat5_rollback.rs)

Treats a filesystem write as an atomic transaction. It reads the previous contents of a target file or marks its non-existence. After writing, it monitors systemic hardware strain. If the system experiences a post-write CPU anomaly (>90%) or Memory leak (>90%), it instantly rewinds the disk to the snapshot state.
8. Worker Node Environment (worker.rs)

The underlying state engine for each concurrent node. It endlessly blocks on its private command line, steps through Moats 3, 2, and 5 sequentially for every valid task, safely commits files to disk, and pushes sealed success or failure crypts back up to the manager.
🪵 Simulation Analysis (Built-in Task Battery)

The system includes a pre-configured integration batch inside main.rs that demonstrates how the different moats catch specific profiles of malicious or valid behavior:

    Task 1 & 2 (Valid Writes): Clean payloads targeting standard files inside ./output/. They cruise effortlessly through Moats 1, 3, 2, and 5, generating a nominal system status report.

    Task 3 (Directory Traversal Attack): An attack attempting to inject ../../../etc/passwd into the path. Result: Blocked immediately at Moat 1. The task never reaches the Manager's inner queue or any worker pipeline.

    Task 4 (Malicious Command Execution Injection): A file targeting a valid output path but containing hidden malware (std::process::Command::new("rm").spawn()). Result: Safely slips through Moat 1, but is instantly trapped and terminated by Moat 3 inside the worker thread. No disk alterations occur.
